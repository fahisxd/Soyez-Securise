Protecting passwords goes far beyond simply storing text in a database. We never store passwords in plain form. Sensitive information is encrypted using modern cryptographic techniques designed to keep your data secure even if unauthorized access occurs. Keys are derived from your master password, ensuring that only you can unlock and access your stored credentials. Through layered security measures, encryption, and privacy-focused design, we aim to make your passwords accessible to you — and unreadable to everyone else.

The listing system is responsible for securely organizing and displaying stored credential entries associated with the authenticated user. Instead of exposing sensitive password data directly, the system first retrieves structured account information such as service names and associated usernames, allowing users to identify stored credentials safely and efficiently. Password secrets remain protected through encrypted storage mechanisms and are only processed when explicitly requested through authenticated verification flows.

Get Password

soyez securise retrieves stored credentials through a secure multi-step verification flow designed around a zero-knowledge-inspired architecture. When a user requests a password, the frontend first requests a temporary nonce from the backend. This nonce is signed locally using an authentication key derived from the user's master password through Argon2id and HKDF key separation. The server independently verifies this HMAC signature before allowing access to any encrypted vault data. Once verified, only the encrypted credential blob is returned from PostgreSQL. Decryption never occurs on the server; instead, the client uses the locally derived vault encryption key stored only in browser memory to decrypt the data. This ensures that even if the database were compromised, attackers would only obtain encrypted data and would still require the user's master-password-derived key material to recover the original credentials.

Security Settings

Master Password Security

Your master password is the foundation of your vault security. It should be:

  • Unique and strong (12+ characters recommended)
  • Always kept private and never shared
  • Never written down or stored openly
  • Changed periodically for enhanced security

Encryption Information

Your vault uses modern encryption standards:

  • Master Password: Argon2id key derivation
  • Stored Credentials: AES-256-GCM encryption
  • Authentication: HMAC-SHA256 verification
  • All operations: Zero-knowledge architecture
